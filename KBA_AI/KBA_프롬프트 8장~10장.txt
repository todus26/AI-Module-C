5. 1년간 80% 이상 출근한 직원에게 15일의 유급휴가를 부여하며, 미사용 연차는 연차수당으로 보상한다.
6. 인사위원회 심의를 거쳐 징계 사유가 타당하다고 인정될 경우 해고할 수 있다.

#RAG 기반 Flask 웹앱 개발 프롬프트

## 1. 목표
- 이 프로젝트는 PDF 문서를 업로드하고, 문서 내용을 기반으로 질의응답이 가능한 **RAG 기반 웹 챗봇**을 만드는 것이다.
- 사용자 시나리오: ① 왼쪽 메뉴창에서 PDF 파일 업로드(다중 업로드 가능) → ② 채팅창에서 질문 입력 → ③ 답변 + 참고한 chunk 내용과 페이지 번호 확인
- UI/UX는 ChatGPT와 유사한 형태(왼쪽 사이드바 + 오른쪽 채팅 영역)로 구성한다.

## 2. 기술 스펙
### 환경 및 프레임워크
- Python 패키지: LangChain 사용
- 로컬 환경에 설치된 패키지 및 버전은 현재 폴더의 `requirements.txt`를 참고할 것
- 웹 프레임워크: Flask
LLM: `gpt-4o-mini` (API Key는 시스템 환경변수에 설정되어 있으므로 코드 내 별도 설정 불필요)
###RAG 파이프라인
- 문서 로딩: `PyPDFLoader`
- 청킹: `RecursiveCharacterTextSplitter` (chunk size 500자, overlap 100자)
- 임베딩: `text-embedding-3-small`
- 벡터 DB: ChromaDB
- 검색: 질문 시 유사도 기준 상위 4개 chunk 검색
- 대화 메모리 기능 포함 (이전 대화 맥락 유지)

### UI 상세
- 왼쪽 메뉴창: 상단에 파일 업로드 버튼 배치 (PDF 다중 업로드 지원)
- 색상 톤: 연한 청색 + 회색 계열, 산뜻하고 깔끔한 느낌
- 채팅창: ChatGPT 스타일의 대화형 인터페이스

### 응답 형식
- 답변 출력 후, 답변 하단에 참고한 chunk 내용 요약 및 페이지 번호를 함께 표시

## 3. 제약조건 & 완료 기준
### 제약조건
- 업로드 가능한 파일 형식은 PDF만 허용 (다른 형식은 업로드 제한 또는 오류 처리)
- 검색된 관련 chunk가 없을 경우, 반드시 "정보가 없어서 답변할 수 없습니다"라고만 응답 (임의로 답변 생성 금지)

### 완료 기준 (Definition of Done)
1. PDF 여러 개를 업로드하면 정상적으로 벡터 DB에 저장된다.
2. 질문 시 관련 chunk 4개를 검색하여 답변에 반영한다.
3. 답변과 함께 참고 chunk 요약 + 페이지 번호가 함께 출력된다.
4. 관련 정보가 없을 경우 지정된 문구로만 응답한다.
5. 이전 대화 맥락을 반영한 대화가 가능하다.

<실습 3 : 계약서 검토 Rag 구현>
===================================================================
내가 만들려고 하는 웹 시스템은 아래와 같아
0. 제목 : LLM 기반 계약서 검토 웹

1. 개요
- 파이썬 langchain 0.3X 버전 패키지를 이용해서 LLM 기반 계약서 검토 웹 코드를 생성해줘
- 계약서 가이드라인이나, 약관을 업로드해서RAG를 구현하고, 사용자가 계약서를 업로드하면
  한 문장씩 읽고,RAG에서 유사 문서를 검색 후, 가이드라인이나 약관에 위배사항이 있는지   검토하고 계약서를 수정해서 출력하는 웹서비스를 구현하는 거야

2. 패키지 버전 및 환경
- flask 패키지를 이용해, llm은 gpt-4o-mini 모델을 사용해
- langchain 등 패키지 버전은 내 시스템에 설치된 ‘requirements.txt' 파일을 참조해줘
- api-key는 나의 시스템 환경에 있으니 설정 안 해도 돼
- 시스템 구현을 위해 추가적으로 필요한 패키지 버전은 알려줘
- 코드들은 이해하기 쉽게 주석을 추가해줘

3. 메뉴 구성
- user interface는 chatgpt와 유사하게 만들어줘    (왼쪽 : 메뉴, 오른쪽 : 채팅 및 결과 )
- 화면 구성은 연한 파랑색과, 연한 회색을 이용해 줘
- 왼쪽 메뉴는 'rag 파일 업로드' 버튼 과  '계약서 업로드' 버튼이 있어야 해
- '계약서 업로드가 완료되면 '계약서 검토' 버튼이 보여야 해
- 오른쪽 화면은 답변을 보여주고, 하단에는 일반적인 질문을 할 수 있는 질문창을 보이게 해줘
-RAG 파일 업로드, 계약서 업로드시 답변 창에 진행율을 보여주고 완료 결과를 출력해줘 (tqdm 패키지 활용, 프로그레스 바 출력)

4.RAG 구현
- 'rag 파일 업로드' 버튼을 누르면 pdf 파일을 업로드 할 수 있도록 구성해줘
- PyPDFLoader로 여러 개의 파일을 업로드 할 수 있어야 해
- 업로드한 문서를 RecursiveCharacterTextSplitter로  30글자로 분할, 5글자로 오버랩 해줘, separators는 ["\n", "\n\n"]
- text-embedding-3-small 로 임베딩하고 chroma DB에 저장해

5 계약서 검토 구현
- '계약서 업로드' 버튼을 누르면 PyPDFLoader로 pdf 파일을 업로드 할 수 있게 해줘
- 계약서를 RecursiveCharacterTextSplitter로  30글자로 분할, 오버랩 하지마, separators는 ["\n", "\n\n"]
- 계약서 문장과RAG 문서를 비교하여 계약서 문장에 오류 또는 보완이 필요한 부분을 찾은 후 수정해줘
- 계약서 문장을 '[원문]' 이라고 표시 후 출력하고 오류를 수정한 문장을 '[수정 문구]' 라고 표시한 후  진한 파란 글씨체로 원문의 바로 밑에 출력해줘 (7. 출력 예시 참조)
- 계약서 문장에 이상이 없다면 원문만 출력하면 됨
- 화면에 문장 하나씩 하나씩 출력해줘, 한꺼번에 출력되면 검토하는 동안 진행 여부를 확인할 수 없어

6. 기타
- 사용자가 일반적인 질문을 하게 되면RAG를 이용하지 말고 llm에 직접 요청해서 답변을 생성해
