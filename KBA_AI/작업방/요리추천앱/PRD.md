# 냉장고 재료 기반 요리 추천 앱 PRD

## Problem Statement

집에서 요리하려는 사용자는 냉장고에 어떤 재료가 있는지, 무엇이 곧 상할지, 지금 가진 재료로 어떤 요리를 만들 수 있는지를 매번 머릿속으로 따져야 한다. 그 결과 유통기한이 지난 재료를 버리게 되고, "오늘 뭐 해 먹지"를 고민하는 시간이 길어지며, 요리를 정한 뒤에야 재료가 부족하다는 것을 알게 된다.

사용자는 가진 재료를 한 곳에서 관리하고, 그 재료로 만들 수 있는 요리와 부족한 재료를 한눈에 보고, 선택한 요리의 분량과 조리 순서를 바로 확인하고 싶어 한다.

## Solution

Gradio로 만든 웹앱이다. 상단 네비게이션 바로 세 페이지를 오간다.

- **재료 목록**: 냉장고 재료(재료명, 수량, 유통기한, 분류)를 추가, 수정, 삭제한다. 재료는 SQLite에 저장되어 앱을 다시 켜도 유지된다. 유통기한이 임박했거나 지난 재료와 현재 재료로 요리하기에 부족한 재료를 이 페이지에서 바로 확인할 수 있다.
- **추천 레시피**: 가진 재료로 만들 수 있는 요리를 목록으로 보여준다. 목록은 요리 이름, 조리 시간, 난이도, 칼로리를 한 줄에 보여주고, 요리를 선택하면 재료 분량과 조리 순서를 보여준다. 데이터셋에 맞는 요리가 없으면 OpenAI가 만든 "AI 추천" 레시피를 별도 섹션으로 보여준다.
- **전체 레시피**: 데이터셋의 모든 레시피를 둘러보고 검색한다.

추천은 `recipes.json`(한식 위주, 약 50개)과 현재 재료의 매칭으로 한다. 필수 재료를 모두 가진 요리는 "바로 가능", 필수 재료가 1~2개 부족한 요리는 "조금 부족"으로 표시한다. 유통기한이 임박한 재료를 쓰는 요리를 위에 정렬한다.

## User Stories

### 재료 관리

1. As a 사용자, I want 재료명, 수량, 단위, 유통기한, 분류를 입력해 재료를 추가할 수 있기를, so that 냉장고 속 재료를 앱에 기록할 수 있다.
2. As a 사용자, I want 재료를 텍스트로 직접 입력할 수 있기를, so that 목록에 없는 재료도 빠르게 추가할 수 있다.
3. As a 사용자, I want 자주 쓰는 재료 목록에서 체크박스로 재료를 고를 수 있기를, so that 일일이 타이핑하지 않아도 된다.
4. As a 사용자, I want 여러 재료를 한 번에 추가할 수 있기를, so that 장을 본 직후 한꺼번에 등록할 수 있다.
5. As a 사용자, I want 저장된 재료의 수량이나 유통기한을 수정할 수 있기를, so that 일부를 사용하거나 정보를 잘못 입력했을 때 바로잡을 수 있다.
6. As a 사용자, I want 재료를 삭제할 수 있기를, so that 다 먹었거나 버린 재료를 목록에서 정리할 수 있다.
7. As a 사용자, I want 앱을 껐다 켜도 재료가 그대로 남아 있기를, so that 매번 다시 입력하지 않아도 된다.
8. As a 사용자, I want 재료를 분류(채소, 육류, 유제품 등)별로 볼 수 있기를, so that 냉장고 구성을 쉽게 파악할 수 있다.
9. As a 사용자, I want 같은 재료를 다시 추가하면 중복 항목이 생기지 않고 병합되거나 경고가 뜨기를, so that 목록이 지저분해지지 않는다.
10. As a 사용자, I want 수량이 0 이하이거나 재료명이 비어 있을 때 오류 메시지를 보기를, so that 잘못된 데이터가 저장되지 않는다.

### 유통기한 관리

11. As a 사용자, I want 유통기한이 D-3 이내인 재료가 "임박"으로 눈에 띄게 표시되기를, so that 상하기 전에 먼저 쓸 수 있다.
12. As a 사용자, I want 유통기한이 지난 재료가 "만료"로 따로 표시되기를, so that 버릴 재료를 알 수 있다.
13. As a 사용자, I want 목록을 유통기한 순으로 정렬할 수 있기를, so that 먼저 먹어야 할 재료를 위에서 볼 수 있다.
14. As a 사용자, I want 유통기한 입력을 비워둘 수 있기를, so that 소금처럼 기한이 중요하지 않은 재료도 등록할 수 있다.
15. As a 사용자, I want 만료된 재료가 추천 매칭에서 자동으로 제외되기를, so that 상한 재료를 쓰는 요리를 추천받지 않는다.

### 요리 추천

16. As a 사용자, I want 가진 재료로 만들 수 있는 요리 목록을 볼 수 있기를, so that 장을 더 보지 않고 요리를 정할 수 있다.
17. As a 사용자, I want 필수 재료를 모두 가진 요리가 "바로 가능"으로 표시되기를, so that 지금 바로 만들 수 있는 요리를 알 수 있다.
18. As a 사용자, I want 필수 재료가 1~2개 부족한 요리가 "조금 부족"으로 함께 표시되기를, so that 조금만 사 오면 만들 수 있는 요리도 고려할 수 있다.
19. As a 사용자, I want 각 요리에서 부족한 재료의 이름을 확인할 수 있기를, so that 무엇을 사야 하는지 알 수 있다.
20. As a 사용자, I want 유통기한이 임박한 재료를 쓰는 요리가 목록 위쪽에 정렬되기를, so that 재료를 버리지 않고 소진할 수 있다.
21. As a 사용자, I want 목록의 각 요리에 이름, 조리 시간, 난이도, 칼로리가 함께 보이기를, so that 한눈에 비교하고 고를 수 있다.
22. As a 사용자, I want 목록에서 요리를 선택하면 재료 분량과 조리 순서가 나타나기를, so that 바로 따라서 요리할 수 있다.
23. As a 사용자, I want 상세 화면에서 내가 가진 재료와 없는 재료가 구분되어 보이기를, so that 준비 상태를 바로 알 수 있다.
24. As a 사용자, I want 소금, 기름, 간장 같은 기본 양념이 항상 있다고 가정되기를, so that 양념까지 일일이 입력하지 않아도 된다.
25. As a 사용자, I want 재료가 하나도 없을 때 안내 메시지를 보기를, so that 먼저 재료를 등록해야 한다는 것을 알 수 있다.
26. As a 사용자, I want 맞는 요리가 하나도 없을 때 그 사실과 대안이 안내되기를, so that 빈 화면에서 막히지 않는다.
27. As a 사용자, I want 재료를 추가, 삭제한 뒤 추천 결과가 갱신되기를, so that 항상 최신 재료 기준으로 추천받을 수 있다.

### 재료 목록 페이지의 부족 재료 표시

28. As a 사용자, I want 추천 페이지로 이동하지 않고 재료 목록 페이지에서도 부족한 재료를 볼 수 있기를, so that 장보기 목록을 바로 만들 수 있다.
29. As a 사용자, I want 부족한 재료가 어떤 요리에 필요한지 함께 보이기를, so that 무엇을 사면 어떤 요리가 가능해지는지 알 수 있다.

### AI 추천

30. As a 사용자, I want 데이터셋에 맞는 요리가 없을 때 AI가 만든 레시피를 받을 수 있기를, so that 특이한 재료 조합에서도 제안을 얻을 수 있다.
31. As a 사용자, I want AI 추천이 데이터셋 추천과 구분되어 "AI 추천" 섹션에 표시되기를, so that 검증된 레시피와 생성된 레시피를 혼동하지 않는다.
32. As a 사용자, I want AI 레시피도 조리 시간, 난이도, 칼로리, 재료 분량, 조리 순서를 같은 형식으로 보기를, so that 일관된 방식으로 읽을 수 있다.
33. As a 사용자, I want API 키가 없거나 호출에 실패해도 앱의 나머지 기능이 정상 동작하기를, so that AI가 안 돼도 앱을 쓸 수 있다.
34. As a 사용자, I want AI 레시피가 저장되지 않고 매번 새로 생성되기를, so that 데이터셋이 오염되지 않는다.

### 전체 레시피

35. As a 사용자, I want 전체 레시피를 한 목록에서 둘러볼 수 있기를, so that 재료와 무관하게 요리 아이디어를 얻을 수 있다.
36. As a 사용자, I want 요리 이름이나 재료로 레시피를 검색할 수 있기를, so that 원하는 레시피를 빨리 찾을 수 있다.
37. As a 사용자, I want 전체 레시피에서도 요리를 선택하면 분량과 조리 순서를 볼 수 있기를, so that 추천 페이지와 같은 방식으로 쓸 수 있다.

### 탐색과 사용성

38. As a 사용자, I want 상단 네비게이션 바로 모든 페이지를 오갈 수 있기를, so that 어디서든 원하는 화면으로 이동할 수 있다.
39. As a 사용자, I want 화면이 장식 없이 단순하고 직관적이기를, so that 학습 없이 바로 사용할 수 있다.
40. As a 사용자, I want 모든 화면 문구가 한국어이기를, so that 편하게 읽을 수 있다.

## Implementation Decisions

### 기술 스택

- 웹 프레임워크는 Gradio의 다중 페이지 기능과 내장 네비게이션 바를 사용한다. 이미 설치된 Gradio 6.x를 쓴다.
- 저장소는 SQLite이다. 별도 서버나 설치가 필요 없고 앱을 재시작해도 재료가 유지된다.
- AI 호출은 OpenAI를 쓴다. API 키는 환경변수 `OPENAI_API_KEY`에서만 읽고 코드나 파일에 저장하지 않는다.
- 레시피 데이터셋은 `data` 폴더의 `recipes.json`이며, 정적 파일로서 앱이 읽기만 한다.

### 모듈

- **재고 저장소**: 재료의 추가, 수정, 삭제, 조회를 담당한다. 재료는 재료명, 수량, 단위, 유통기한(선택), 분류를 가진다. UI와 추천 로직을 모른다.
- **유통기한 판정**: 오늘 날짜와 유통기한으로 "정상 / 임박(D-3 이내) / 만료 / 기한 없음"을 판정한다.
- **재료명 정규화**: 같은 재료의 다른 표기(달걀/계란, 파/대파 등)를 하나로 묶는다. 매칭 정확도를 위해 둔다.
- **추천 엔진**: 재고와 레시피 목록, 오늘 날짜를 받아 추천 목록을 돌려주는 순수 로직이다. 이 프로젝트의 핵심 모듈이다.
- **레시피 저장소**: `recipes.json`을 읽어 레시피를 제공하고, 이름과 재료로 검색한다.
- **AI 레시피 생성기**: 현재 재료로 레시피를 생성하고 구조화된 결과를 돌려준다. 실패와 키 부재를 호출자가 구분할 수 있게 알린다.
- **UI 레이어**: 세 페이지(재료 목록, 추천 레시피, 전체 레시피)와 네비게이션 바를 구성한다. 비즈니스 로직은 위 모듈에 위임한다.

### 추천 엔진 계약

- 입력: 현재 재고, 전체 레시피, 오늘 날짜.
- 만료된 재료는 재고에서 제외하고 매칭한다.
- 레시피의 재료는 필수 재료와 기본 양념으로 나뉜다. 기본 양념은 항상 있다고 가정해 매칭에서 제외한다.
- 판정은 두 가지다. 필수 재료를 모두 가지면 "바로 가능", 1~2개 부족하면 "조금 부족"이다. 3개 이상 부족하면 목록에서 제외한다.
- 필수 재료를 하나도 가지고 있지 않은 요리는 부족 개수와 관계없이 제외한다. 재고가 비어 있으면 추천 결과도 비어 있다.
- 매칭은 재료의 보유 여부만 본다. 수량과 단위는 비교하지 않는다.
- 정렬 우선순위는 다음과 같다. (1) "바로 가능"을 "조금 부족"보다 앞에 둔다. (2) 같은 판정 안에서는 유통기한 임박 재료를 많이 사용하는 요리를 앞에 둔다. (3) 필수 재료 일치율이 높은 요리를 앞에 둔다. (4) 조리 시간이 짧은 요리를 앞에 둔다.
- 출력: 요리별로 판정, 부족한 필수 재료 목록, 사용하는 임박 재료 목록을 담는다.

### 레시피 데이터 스키마

- 레시피 하나는 이름, 조리 시간(분), 난이도, 칼로리, 필수 재료(이름, 분량), 기본 양념(이름, 분량), 조리 순서(단계 목록)를 가진다.
- 난이도는 쉬움/보통/어려움 세 단계로 한다.
- 한식 위주로 약 50개를 작성한다. 재료 조합이 다양하도록 구성한다.

### 페이지 구성

- **재료 목록 페이지**: 재료 입력(텍스트 입력과 체크리스트 선택), 재료 표, 유통기한 상태 표시, 삭제와 수정, 부족한 재료 표시를 포함한다. 사진 입력은 없다.
- **추천 레시피 페이지**: 추천 목록(이름, 조리 시간, 난이도, 칼로리, 판정), 선택한 요리의 상세(분량, 조리 순서), "AI 추천" 섹션을 포함한다.
- **전체 레시피 페이지**: 전체 목록, 검색, 선택 시 상세를 포함한다.
- 기존 "추천 결과"라는 이름은 "추천 레시피"로 부른다.

### AI 추천 동작

- 데이터셋에서 맞는 요리가 없을 때, 그리고 "AI 추천" 섹션에서 사용자가 요청했을 때만 호출한다.
- 생성된 레시피는 저장하지 않으며 화면에 "AI 추천"으로 구분 표시한다.
- 키가 없거나 호출이 실패하면 오류를 화면에 알리고 나머지 기능은 그대로 동작한다.

### 사용 가능한 환경

- 실행 환경에는 Gradio, openai, langchain-openai가 이미 설치되어 있다.
- 환경변수에 `OPENAI_API_KEY`가 존재하는 것을 확인했다.

## Testing Decisions

### 좋은 테스트의 기준

- 외부에서 관찰 가능한 동작만 검증한다. 내부 함수 구조나 호출 순서는 검증하지 않는다.
- 날짜는 고정해서 주입하고, 현재 시각에 의존하지 않는다.
- 네트워크가 필요한 AI 호출은 테스트에서 호출하지 않는다.

### 테스트 seam

- seam은 하나로 한다. 가장 높은 지점인 **추천 엔진의 공개 인터페이스**(재고, 레시피, 오늘 날짜를 넣고 추천 목록을 받는 지점)다. 유통기한 판정과 재료명 정규화는 이 seam을 통해 간접적으로 검증한다.
- UI와 AI 생성기는 seam에 포함하지 않는다.

### 검증할 동작

- 필수 재료를 모두 가지면 "바로 가능"이다.
- 필수 재료가 1~2개 부족하면 "조금 부족"이고 부족한 재료 이름이 맞게 나온다.
- 3개 이상 부족하면 결과에서 제외된다.
- 기본 양념이 없어도 매칭에 영향을 주지 않는다.
- 만료된 재료는 매칭에서 제외된다.
- D-3 이내 재료를 쓰는 요리가 같은 판정 안에서 앞에 정렬된다.
- 달걀/계란 같은 동의어가 같은 재료로 매칭된다.
- 재고가 비어 있으면 빈 결과를 돌려준다.

### 선행 사례

- 같은 저장소의 `pdf분할병합`과 `유튜브다운로드` 프로젝트가 pytest로 순수 로직을 테스트한 사례가 있다. 같은 방식을 따른다.

## Out of Scope

- 냉장고 사진 인식(YOLO 및 비전 LLM)과 사진 업로드 입력.
- 재료 수량, 단위 비교와 인분 수에 따른 분량 자동 환산.
- 요리 이미지 표시.
- AI가 생성한 레시피의 저장과 데이터셋에의 누적.
- 다중 사용자, 로그인, 계정별 재고 분리.
- 장보기 목록의 내보내기나 공유.
- 모바일 앱, 푸시 알림.
- 영양 정보의 정밀 계산(칼로리는 레시피에 적힌 대략값을 쓴다).

## Further Notes

- 이 PRD는 질문 1~18번의 문답 결과를 정리한 것이다. 구현은 완료되었다.
- 구현 중 정리한 규칙: 정렬은 판정이 우선이고 임박 재료 사용 수는 같은 판정 안에서 적용한다. 보유 재료가 하나도 겹치지 않는 요리는 추천하지 않는다.
- 재료 목록 저장 위치는 기본적으로 `data/pantry.db`이며, 환경변수 `PANTRY_DB_PATH`로 바꿀 수 있다. 테스트는 이 값을 임시 경로로 지정해 실제 데이터를 건드리지 않는다.
- 사진 인식은 초기 논의에서 후보였으나 17번 답변으로 범위에서 제외됐다. 이 때문에 YOLO를 쓰는 앞선 프로젝트와는 의존 관계가 없다.
- 13번 답변의 "B추천 결과를 추천 레시피 이름으로"는 "추천 결과" 페이지 이름을 "추천 레시피"로 바꾸라는 뜻으로 해석했다.
- 아직 정하지 않은 사항: 화면의 세부 레이아웃, 재료명 동의어 목록의 범위, 체크리스트에 올릴 자주 쓰는 재료의 구성, 사용할 OpenAI 모델.
- 이 폴더의 `requirements.txt`는 환경 전체 패키지 목록이다. 앱에 필요한 의존성만 따로 정리할지는 구현 시 정한다.
