# Architecture: 영업기회 발굴 Agent

## 1. 목적과 범위

영업 담당자가 지도에서 거래처를 선택하면 거래처 정보, 매출, 방문일지, 뉴스를 한 화면에서 확인하고, 이를 바탕으로 방문 준비 보고서를 작성할 수 있는 웹 앱이다.

범위
- 거래처 위치를 지도에 핀으로 표시하고 상태별로 색을 구분한다.
- 핀에 마우스를 올리면 요약 정보를, 클릭하면 상세 정보와 뉴스를 보여준다.
- 선택한 거래처의 데이터를 바탕으로 보고서 초안을 생성하고, 사용자가 수정해 저장한다.
- 위치 정보가 없는 거래처는 별도 목록으로 분리해 같은 방식으로 조회할 수 있게 한다.

범위 제외
- 이메일 발송, 제안서 작성 (자료에 포함되지 않음)
- 외부 사이트 실시간 크롤링 (9절 참고)

## 2. 기술 스택

| 영역 | 선택 | 비고 |
|---|---|---|
| UI 프레임워크 | Streamlit | 사이드바, 컬럼 레이아웃, 파일 변경 감지에 적합 |
| 지도 | folium + streamlit-folium | 핀 색상, hover 툴팁, 클릭 이벤트 반환을 지원 |
| 데이터 처리 | pandas, openpyxl | Excel 읽기 |
| 보고서 생성 | LLM API | 사용 모델과 API는 미정 (11절) |
| 설정 | python-dotenv, config.py | API 키는 환경변수로 관리 |

Gradio도 사용할 수 있으나, 지도 위 핀의 hover와 클릭 연동은 Streamlit + folium 조합이 구현이 단순하다.

## 3. 디렉터리 구조

```
sales-opportunity-agent/
  app.py                  # 진입점, 화면 구성
  config.py               # 경로, 컬럼 매핑, 임계값, 툴팁 항목, 테마 값
  .env                    # LLM API 키 (저장소에 포함하지 않음)
  data/
    customer_info.xlsx
    customer_meeting.xlsx
    customer_news.xlsx
    customer_sales.xlsx
  src/
    data_loader.py        # Excel 로드, 컬럼 매핑, 캐시
    status.py             # 거래처 상태 분류
    map_view.py           # 지도 및 핀 생성
    detail_panel.py       # 상세 패널, 뉴스 목록
    unlocated.py          # 위치 미확인 거래처 목록
    report.py             # 보고서 생성 및 저장
    theme.py              # 색상, 스타일
  prompts/
    report_system.md      # 보고서 생성용 LLM 지시문
  docs/
    Prompts.md
    Architecture.md
    UI.md
```

Excel 확장자는 실제 파일 기준으로 맞춘다.

## 4. 데이터 소스

| 파일 | 내용 | 주요 용도 |
|---|---|---|
| customer_info | 거래처 기본정보 (위치, 산업군 등) | 핀 위치, 기본 현황, 위치 미확인 판별 |
| customer_sales | 거래처 매출, 주요 구매 품목 | 매출 추이, 구매 감소 판단 |
| customer_meeting | 방문일지 (미팅 이력, 요청사항) | 최근 방문, 반복 요청 판단, 보고서 근거 |
| customer_news | 거래처 및 산업군 관련 뉴스 | 클릭 시 뉴스 표시, 영업기회 도출 근거 |

각 파일의 컬럼명은 자료에 제시되지 않았다. 구현 전에 실제 파일의 컬럼을 출력해 확인하고, 모든 컬럼 참조는 `config.py`의 `COLUMN_MAP` 한 곳에서 관리한다. 코드 안에 컬럼명을 직접 쓰지 않는다.

거래처를 파일 간에 연결하는 키(거래처 코드 또는 거래처명)도 확인이 필요하다. 거래처명으로 연결해야 하는 경우 표기 차이(공백, 법인 표기)를 정규화하는 처리를 넣는다.

## 5. 모듈 구성

| 모듈 | 책임 |
|---|---|
| data_loader | 4개 파일 로드, 컬럼명을 내부 표준 이름으로 변환, 파일 수정시간 기반 캐시 |
| status | 거래처별 상태(신규, 일반, 위험) 계산 |
| map_view | 위치가 있는 거래처를 핀으로 표시, 툴팁 구성, 클릭된 거래처 반환 |
| detail_panel | 선택 거래처의 요약, 매출, 방문 이력, 뉴스 표시 |
| unlocated | 위치 정보가 없는 거래처 목록과 선택 처리 |
| report | 보고서 입력 데이터 구성, LLM 호출, 결과 편집·저장 |
| theme | 색상과 스타일 값 정의 |

## 6. 데이터 흐름

```
Excel 4종
  -> data_loader (로드, 매핑, 캐시)
  -> status (거래처별 상태 계산)
  -> 거래처 테이블 (info + 상태 + 최근 매출/방문 요약)
       |-- 위치 있음 -> map_view (핀)
       |-- 위치 없음 -> unlocated (목록)
  -> 사용자가 핀 또는 목록에서 거래처 선택 (selected_customer)
  -> detail_panel (요약, 매출, 방문 이력, 뉴스)
  -> 사용자가 뉴스 선택 후 보고서 작성 요청
  -> report (거래처 데이터 + 선택 뉴스 -> LLM -> 초안)
  -> 사용자가 수정 후 저장 또는 다운로드
```

선택된 거래처는 `st.session_state["selected_customer"]`로 관리한다. 지도 클릭과 위치 미확인 목록 선택이 같은 상태값을 갱신하도록 한다.

## 7. 거래처 상태 분류

| 상태 | 핀 색상 | 의미 |
|---|---|---|
| 신규 | 노랑 | 거래를 시작한 지 얼마 되지 않은 거래처 |
| 일반 | 초록 | 보통 상태 |
| 위험 | 빨강 | 거래 관계 점검이 필요한 신호가 있는 거래처 |

판정 우선순위는 위험, 신규, 일반 순서로 한다. 신규이면서 위험 신호가 있으면 위험으로 표시한다. 이 순서는 확정이 필요하다.

과제 설명에서 위험 신호로 언급된 것은 구매 감소와 반복되는 요청사항이다. 각 조건의 구체적 기준은 자료에 없으므로 `config.py`의 값으로 분리한다.

| 설정 항목 | 설명 | 값 |
|---|---|---|
| NEW_CUSTOMER_DAYS | 거래 시작 후 신규로 보는 기간 | 미정 |
| SALES_DECLINE_RULE | 구매 감소 판단 방식 (비교 기간, 감소율) | 미정 |
| REPEAT_REQUEST_RULE | 반복 요청 판단 방식 (기간, 횟수) | 미정 |
| REFERENCE_DATE | 기준일 | 실행일 |

거래 시작일은 customer_info에 있는지, 없으면 customer_sales의 첫 거래 시점으로 대체할지 확인이 필요하다.

## 8. 위치 정보 처리

- customer_info에 위도, 경도가 있으면 그대로 사용한다.
- 값이 비어 있거나 유효 범위를 벗어난 거래처는 위치 미확인으로 분류한다.
- 주소만 있고 좌표가 없는 경우 지오코딩을 할지는 미정이다. 1차 구현에서는 하지 않고 위치 미확인으로 둔다.

## 9. 뉴스 처리

요구사항에는 news 파일에서 크롤링한 정보를 보여주는 것으로 되어 있다. 이 문서는 customer_news 파일에 이미 수집된 뉴스가 들어 있고, 앱은 그 파일을 읽어 표시하는 것으로 가정한다. 앱이 외부 사이트를 직접 크롤링하는 구조가 아니다.

- 선택한 거래처의 키로 customer_news를 필터링한다.
- 날짜 컬럼이 있으면 최신순으로 정렬한다.
- 거래처별 뉴스 외에 산업군 뉴스도 있다면 같은 산업군 뉴스를 함께 보여줄지 확인이 필요하다.

앱이 직접 크롤링해야 한다면 범위가 달라지므로 별도로 결정한다.

## 10. 보고서 생성

입력
- 선택한 거래처의 기본정보, 매출·주요 구매 품목, 방문일지, 사용자가 선택한 뉴스
- 계산된 상태와 그 판정 근거

출력 섹션
1. 고객 현황
2. 매출 및 구매 추이
3. 최근 방문 내용 및 요청사항
4. 최근 뉴스 및 산업 동향
5. 영업기회
6. 위험요인
7. 방문 시 확인사항
8. 근거 (사용한 데이터 출처)

처리 원칙
- 입력 데이터에 없는 사실은 쓰지 않는다. 데이터가 부족한 항목은 "자료 없음"으로 표시한다.
- 영업기회와 위험요인에는 근거가 된 데이터(뉴스 제목, 매출 변화, 방문일지 날짜)를 함께 적는다.
- 결과는 초안이며, 사용자가 화면에서 수정한 뒤 저장한다. 최종 판단과 승인은 사용자가 한다.
- 지시문은 `prompts/report_system.md`로 분리해 코드 수정 없이 바꿀 수 있게 한다.

저장 형식은 미정이다. 기본값은 화면 미리보기와 Markdown 다운로드로 하고, Word 등 다른 형식은 확인 후 추가한다.

## 11. 미결 사항

| 항목 | 현재 처리 |
|---|---|
| 4개 파일의 컬럼명과 연결 키 | 파일 확인 후 COLUMN_MAP에 반영 |
| 신규, 위험 판정 기준과 수치 | config 값으로 분리, 현업 확정 필요 |
| 상태 판정 우선순위 | 위험 > 신규 > 일반으로 가정 |
| 거래 시작일 컬럼 존재 여부 | 확인 필요 |
| 주소만 있는 거래처의 좌표 변환 | 1차 구현에서 제외 |
| 호버 툴팁에 표시할 항목 | UI.md의 기본안 사용, config에서 변경 |
| 뉴스 범위 (거래처 단위만 또는 산업군 포함) | 확인 필요 |
| 보고서 생성에 사용할 LLM과 API | 확인 필요 |
| 보고서 저장 형식 | Markdown 다운로드를 기본으로 하고 확인 필요 |
| 시프티블루의 정확한 색상 코드 | 임시값 사용, 확인 필요 |
| 접근권한(담당 거래처 범위 제한 여부) | 자료에 없음 |

## 12. 비기능 사항

- 핀 hover 툴팁은 지도에 포함된 정보만 사용해 서버 호출 없이 표시한다.
- 데이터 로드는 파일 수정시간을 캐시 키로 사용해, 매일 새로 생성되는 파일이 자동으로 반영되도록 한다.
- 파일이 없거나 컬럼이 맞지 않으면 화면에 어떤 파일의 어떤 컬럼이 문제인지 표시한다.
- LLM 호출 실패 시 오류 메시지를 보여주고 재시도할 수 있게 한다. 사용자가 편집 중이던 내용은 유지한다.
- API 키는 코드나 저장소에 넣지 않는다.
