# Prompts: 영업기회 발굴 Agent

Cursor에 순서대로 하나씩 입력하는 프롬프트 모음이다. 각 단계의 결과를 확인한 뒤 다음 단계로 넘어간다.
모든 프롬프트는 `docs/Architecture.md`와 `docs/UI.md`를 기준으로 하므로 두 파일을 먼저 프로젝트에 넣어 둔다.

## 공통 규칙 (Cursor 규칙 파일 또는 첫 프롬프트에 포함)

```
이 프로젝트는 영업 담당자가 거래처를 지도에서 선택해 방문 준비 보고서를 작성하는 Streamlit 앱이다.
작업 전에 docs/Architecture.md와 docs/UI.md를 읽고 그 내용을 따른다.

규칙
- Excel 컬럼명을 추측하지 않는다. 실제 파일을 읽어 확인하고, 컬럼 참조는 config.py의 COLUMN_MAP에서만 한다.
- 임계값, 색상, 툴팁 항목은 코드에 직접 쓰지 않고 config.py와 theme.py에 둔다.
- API 키는 .env에서 읽고 코드에 쓰지 않는다.
- 화면 문구와 주석에 이모지를 쓰지 않는다.
- 한 번에 요청한 단계만 구현한다. 다음 단계의 기능을 미리 만들지 않는다.
- 문서에 "미정"으로 되어 있는 값은 임의로 정하지 말고, config 값으로 두고 어떤 값이 필요한지 알려준다.
```

## 1단계. 프로젝트 초기화와 데이터 확인

```
Architecture.md의 디렉터리 구조대로 프로젝트를 만든다.
- requirements.txt: streamlit, folium, streamlit-folium, pandas, openpyxl, python-dotenv
- config.py, .env.example, .streamlit/config.toml, src/ 하위 빈 모듈 생성

data/ 폴더의 customer_info, customer_meeting, customer_news, customer_sales 파일을 읽어서 각 파일의
컬럼명, 행 수, 결측 비율, 샘플 3행을 출력하는 scripts/inspect_data.py를 작성하고 실행한다.

출력 결과를 보고 다음을 정리해서 알려준다.
- 거래처를 파일 간에 연결할 수 있는 키 후보
- 위도, 경도 또는 주소 컬럼 존재 여부
- 거래 시작일로 쓸 수 있는 컬럼 여부
- 뉴스 파일의 제목, 날짜, 출처, 링크 컬럼
COLUMN_MAP은 아직 채우지 말고 이 정리를 먼저 보여준다.
```

완료 기준: 4개 파일의 컬럼 목록과 연결 키 후보가 정리되어 있다. 이 결과를 보고 COLUMN_MAP을 확정한다.

## 2단계. 데이터 로더

```
1단계 결과를 반영해 config.py의 COLUMN_MAP을 작성하고 src/data_loader.py를 구현한다.

- 4개 파일을 읽어 내부 표준 컬럼명으로 변환한다.
- 파일 수정시간을 캐시 키로 사용하는 st.cache_data를 적용한다.
- 거래처 연결 키는 공백과 표기 차이를 정규화한다.
- 파일이 없거나 필요한 컬럼이 없으면, 어떤 파일의 어떤 컬럼인지 알려주는 예외를 발생시킨다.
- 거래처 단위 테이블을 만든다. 기본정보에 최근 매출, 최근 방문일을 붙인 형태이다.
- 좌표가 비어 있거나 유효 범위를 벗어난 거래처에는 has_location=False를 둔다.

간단한 확인 스크립트로 거래처 수, 위치 있음/없음 수를 출력한다.
```

완료 기준: 거래처 단위 테이블이 만들어지고 위치 있음/없음 건수가 출력된다.

## 3단계. 상태 분류

```
src/status.py에 거래처 상태(신규, 일반, 위험)를 계산하는 함수를 구현한다. 기준은 Architecture.md 7절이다.

- 판정 우선순위는 위험, 신규, 일반 순서다.
- 신규 판정 기간, 구매 감소 기준, 반복 요청 기준은 config.py의 NEW_CUSTOMER_DAYS,
  SALES_DECLINE_RULE, REPEAT_REQUEST_RULE에서 읽는다. 값이 비어 있으면 해당 조건은 판정에서 제외하고,
  제외된 조건이 무엇인지 로그로 남긴다.
- 각 거래처에 대해 상태와 함께 판정 근거 문자열을 반환한다. 예: "최근 3개월 매출 감소"
- 거래처 테이블에 status, status_reason 컬럼을 추가한다.

각 조건별로 해당하는 거래처 수를 출력하는 확인 코드를 작성한다.
```

완료 기준: 모든 거래처에 상태와 근거가 붙고, 기준값이 비어 있을 때 오류 없이 동작한다.

## 4단계. 지도

```
src/map_view.py에 folium 지도를 구현한다. 화면 규칙은 UI.md 3절이다.

- has_location=True인 거래처를 핀으로 표시한다.
- 핀 색상은 상태에 따라 신규는 노랑, 일반은 초록, 위험은 빨강이다. 색상 값은 theme.py에서 가져온다.
- 핀에 마우스를 올리면 TOOLTIP_FIELDS에 지정된 항목만 짧게 보여준다.
- 핀 클릭 시 해당 거래처 식별자를 반환하고, app.py에서 st.session_state["selected_customer"]에 저장한다.
- 지도는 모든 핀이 보이도록 초기 범위를 맞춘다.
- 선택된 거래처의 핀은 크기를 키워 구분한다.
- 지도 한쪽에 범례와 상태별 거래처 수를 표시한다.
- 클릭해도 지도의 위치와 확대 수준이 초기화되지 않게 한다.

app.py에 지도만 넣은 화면으로 먼저 확인한다.
```

완료 기준: 핀이 상태별 색으로 표시되고, hover 툴팁과 클릭 선택이 동작한다.

## 5단계. 상세 패널과 뉴스

```
src/detail_panel.py에 선택한 거래처의 상세 패널을 구현한다. 화면 규칙은 UI.md 4절이다.

- 화면을 지도(약 2/3)와 상세 패널(약 1/3)의 두 컬럼으로 나눈다.
- 거래처를 선택하지 않았을 때는 "지도에서 거래처를 선택하세요"를 표시한다.
- 패널 상단에 거래처명과 상태 배지를 표시하고, 요약, 뉴스, 보고서 세 개의 탭을 만든다.
- 요약 탭: 기본 정보, 최근 매출과 주요 구매 품목, 매출 추이 그래프, 최근 방문일지 목록, 상태 근거.
- 뉴스 탭: customer_news에서 선택한 거래처의 뉴스를 최신순으로 나열한다. 제목, 날짜, 출처를 표시하고,
  링크가 있으면 연결한다. 항목마다 체크박스를 두고 기본값은 전체 선택이다. 뉴스가 없으면 안내 문구를 표시한다.
- 뉴스는 파일에 있는 데이터만 사용하고 외부 사이트를 크롤링하지 않는다.
- 보고서 탭은 아직 비워 둔다.
```

완료 기준: 핀 클릭 시 패널의 요약과 뉴스가 해당 거래처 기준으로 바뀐다.

## 6단계. 위치 미확인 거래처와 필터

```
사이드바를 구현한다. 화면 규칙은 UI.md 5절이다.

- 거래처명 검색: 결과를 선택하면 해당 거래처가 선택되고, 위치가 있으면 지도가 그 핀으로 이동한다.
- 상태 필터: 신규, 일반, 위험을 선택하면 지도와 목록에 같은 필터가 적용된다.
- 위치 미확인 거래처: 사이드바 하단에 "위치 미확인 (N)" 접이식 목록을 만든다. 거래처명과 상태를 표시하고,
  선택하면 지도 핀과 같은 방식으로 상세 패널이 열린다. 건수가 0이면 이 구역을 숨긴다.
- 필터 결과가 없으면 "조건에 맞는 거래처가 없습니다"를 표시한다.
```

완료 기준: 위치가 없는 거래처도 목록에서 선택해 같은 상세 패널을 볼 수 있다.

## 7단계. 보고서 생성

```
src/report.py와 보고서 탭을 구현한다. 규칙은 Architecture.md 10절이다.

- 입력: 선택한 거래처의 기본정보, 매출, 방문일지, 뉴스 탭에서 체크한 뉴스, 상태와 판정 근거.
- prompts/report_system.md를 읽어 시스템 지시문으로 사용한다. 이 파일은 아래 부록의 내용으로 만든다.
- LLM 호출 부분은 함수 하나로 분리해 모델과 API를 쉽게 바꿀 수 있게 한다. 사용할 모델과 키는 .env에서 읽는다.
- 보고서 탭의 "보고서 작성" 버튼을 누르면 초안을 생성해 편집 가능한 텍스트 영역에 표시한다.
- 초안 위에 "자동 생성된 초안입니다. 내용을 확인하고 수정하세요."를 표시한다.
- 수정한 내용을 Markdown 파일로 다운로드할 수 있게 한다.
- 호출 실패 시 오류 메시지와 다시 시도 버튼을 표시하고, 사용자가 편집 중인 내용은 유지한다.
- 다른 거래처를 선택하면 이전 보고서가 새 거래처의 것으로 오해되지 않게 초기화한다.
```

완료 기준: 거래처를 선택해 뉴스를 고르고 보고서를 생성, 수정, 다운로드할 수 있다.

## 8단계. 테마와 화면 정리

```
UI.md 6~8절에 맞춰 화면을 정리한다.

- src/theme.py에 색상 값을 정의하고, 다른 파일은 이 값만 참조하게 한다. 기본색은 시프티블루 계열이며
  현재는 임시값(#4A6FA5)을 쓴다.
- .streamlit/config.toml의 primaryColor를 기본색에 맞춘다.
- 상태 배지, 범례, 탭, 버튼에 같은 색 체계를 적용한다.
- 카드와 구분선은 얇은 선으로 처리하고 그림자와 그라데이션은 쓰지 않는다.
- UI.md 7절의 화면 문구를 사용하고, 화면 어디에도 이모지를 쓰지 않는다.
- UI.md 8절의 상태별 화면(로딩, 파일 오류, 필터 결과 없음 등)을 처리한다.
```

완료 기준: 화면 전체가 같은 색 체계를 쓰고, UI.md의 문구와 상태별 처리가 반영되어 있다.

## 9단계. 점검

```
다음을 점검하고 문제가 있으면 수정한다.

- 코드에 컬럼명, 색상 값, 임계값이 직접 쓰여 있는 곳이 없는지
- 4개 파일 중 하나가 없을 때와 컬럼이 바뀌었을 때 오류 메시지가 명확한지
- 위치 미확인 거래처, 뉴스 없는 거래처, 매출 이력이 없는 거래처에서 화면이 깨지지 않는지
- 파일을 교체한 뒤 앱을 다시 불러오면 새 데이터가 반영되는지
- .env와 API 키가 저장소에 포함되지 않는지
- README에 실행 방법(설치, .env 설정, 실행 명령)이 있는지
```

## 부록. 보고서 생성용 지시문 (prompts/report_system.md)

```
당신은 영업 담당자의 고객사 방문 준비를 돕는다. 입력으로 받은 거래처 데이터만 사용해 방문 준비 보고서 초안을 작성한다.

입력
- 거래처 기본정보
- 매출과 주요 구매 품목
- 방문일지(미팅 이력, 요청사항)
- 선택된 뉴스
- 거래처 상태(신규, 일반, 위험)와 판정 근거

작성 원칙
- 입력에 없는 사실은 쓰지 않는다. 정보가 부족한 항목은 "자료 없음"으로 적는다.
- 수치는 입력 데이터의 값을 그대로 사용하고 새로 추정하지 않는다.
- 영업기회와 위험요인에는 근거가 된 데이터(뉴스 제목, 매출 변화, 방문일지 일자)를 함께 적는다.
- 사업 확대 소식은 추가 공급 기회로, 구매 감소와 반복되는 요청사항은 거래 관계 점검 신호로 검토한다.
- 영업기회와 위험요인은 단정하지 않고 "검토가 필요하다"와 같이 담당자가 판단할 수 있는 형태로 쓴다.
- 문장은 짧고 업무 문서에 맞는 어투로 쓴다.

출력 형식 (Markdown, 아래 순서와 제목을 유지)
# {거래처명} 방문 준비 보고서
## 1. 고객 현황
## 2. 매출 및 구매 추이
## 3. 최근 방문 내용 및 요청사항
## 4. 최근 뉴스 및 산업 동향
## 5. 영업기회
## 6. 위험요인
## 7. 방문 시 확인사항
## 8. 근거
```
