#### 1. pdf분할병합 (PyQt5 데스크톱 앱)

- 분할 5가지: 페이지 선택 / 범위별 / N페이지씩 / 특정 페이지 뒤에서 / 균등 분할
- 병합: 여러 PDF를 순서 조정(드래그, 위로/아래로/삭제)해서 하나로 합치기
- 저장 전에 썸네일로 결과를 미리 보고, `수정`을 누르면 입력값이 그대로 남아 있는 상태로 돌아간다.
- 로직(`core`)과 화면(`ui`)을 나누고, 썸네일 생성과 Word 변환은 `QThread`로 처리해서 화면이 멈추지 않게 했다.
- 페이지 입력 파서는 `pytest`로 정상/경계/오류 케이스를 검증했다.
- `PyInstaller`로 `.exe` 파일까지 만들어 봤다.
- 올리지 않은 것: 실행 파일 `dist/PDF분할병합.exe`는 약 126MB라서 GitHub의 100MB 제한에 걸리고, `build/` 폴더는 다시 만들 수 있는 부산물이라 `.gitignore`로 제외했다. 아래 방법으로 직접 만들 수 있다.

**실행 파일(.exe) 만드는 법**

`pdf_tool` 폴더에서 아래를 순서대로 실행한다.

```powershell
pip install -r requirements.txt
pip install pyinstaller
python -m PyInstaller --noconfirm --clean "PDF분할병합.spec"
```

- 결과물은 `dist/PDF분할병합.exe` 하나로 나오고, 더블클릭하면 파이썬이 없는 PC에서도 실행된다. 처음 실행할 때는 압축을 푸느라 몇 초 걸린다.
- `PDF분할병합.spec`에는 창만 띄우는 설정(`console=False`), 아이콘 폴더(`resources`) 포함, `pdf2docx` 모듈 포함, 쓰지 않는 큰 라이브러리 제외가 들어 있다.
- 실행 파일 안에서는 파일 경로가 임시 폴더로 바뀌기 때문에, 아이콘 경로를 찾는 코드(`ui/styles.py`의 `icon_path`)에 `sys._MEIPASS`를 따로 처리해 두었다.
- 빌드 중 `Hidden import "sip" not found` 경고가 나와도 실행에는 문제가 없었다.

#### 3. pdf다운로드 (PDF 번역 웹 서버)

- Flask로 `/`(화면), `/upload`(PDF 업로드), `/translate/<job_id>`(번역), `/download/<job_id>`(결과 받기) 주소를 만들었다.
- PDF 텍스트를 3000자 단위로 쪼개서 OpenAI에 보내고, 번역되는 대로 화면에 이어 붙이도록 SSE(서버가 계속 데이터를 흘려 보내는 방식)를 사용했다.
- 암호가 걸린 PDF, 스캔본(텍스트 없음), 번역 실패 시 재시도 같은 예외 상황을 처리했다.
- API 키는 코드에 쓰지 않고 환경 변수 `OPENAI_API_KEY`로 읽는다.

**실습하면서 알게 된 것: 패키지 목록 정리하기 (`requirements.txt`)**

```powershell
pip list >> requirements.txt
pip freeze > requirements.txt
pip install -r requirements.txt
```

- `pip list >> requirements.txt`
  - 커서(코딩 에이전트)가 코드를 만들고 실행하려면 패키지가 설치돼 있어야 하는데, 목록이 없으면 내 컴퓨터를 돌아다니며 찾느라 시간과 토큰이 많이 든다.
  - 이 명령어로 패키지 목록을 파일로 만들어 두면 어떤 패키지가 있는지, 설치가 필요한 게 무엇인지 바로 알 수 있어서 코드를 만들기가 쉬워진다.
  - 이 파일은 **커서가 읽는 참고용**이다. 형식이 설치용이 아니라서 `pip install`로는 설치되지 않는다.
  - `>`는 파일을 덮어쓰고, `>>`는 기존 내용은 두고 뒤에 이어 붙인다.
- `pip freeze > requirements.txt`
  - 내 코드를 다른 사람에게 주려면 상대방에게도 파이썬이 있어야 하고, 내가 쓴 것과 같은 버전의 패키지가 설치돼 있어야 한다.
  - `pip freeze`는 내 PC에 설치된 패키지를 `패키지==버전` 형식으로 뽑아 준다.
- `pip install -r requirements.txt`
  - 받은 사람이 이 명령어를 실행하면 파일에 적힌 버전 그대로 한 번에 설치된다.

### 실습 1. 영상·이미지 분석 (`작업방/영상이미지분석`)

사진이나 웹캠 영상에서 사물을 찾아 네모 박스와 이름을 표시하는 앱을 만들었다. 모델은 YOLO11(`yolo11n.pt`)을 썼다.

- 서버 주소
  - `http://127.0.0.1:5000/` : Flask로 서버를 띄웠을 때의 기본 주소
  - `http://127.0.0.1:7860/` : Gradio로 서버를 띄웠을 때의 기본 주소
  - 저장소에 있는 `app.py`는 Gradio 버전이다.
- `app.py` (Gradio)
  - 왼쪽은 이미지 업로드, 오른쪽은 웹캠 실시간 탐지로 화면을 나눴다.
  - 탐지된 사물마다 박스, 클래스 이름, 신뢰도(예: `person 0.91`)를 그려서 돌려준다. 신뢰도 0.25 미만은 걸러낸다.
  - 웹캠은 0.1초마다 프레임을 받아 탐지하고, 모델이 동시에 여러 번 불리지 않도록 `Lock`으로 감쌌다.
- 가중치 파일(`yolo11n.pt`)
  - 이미 학습이 끝난 모델의 값을 담은 파일이다. 코드에서 `YOLO("yolo11n.pt")`로 불러다 쓰기만 하면 되고, 직접 학습하지 않아도 사물을 찾을 수 있다.
  - 약 5MB라서 저장소에 같이 올렸다. (100MB가 넘는 모델 파일은 GitHub 용량 제한 때문에 `.gitignore`로 제외해 둔 상태다.)
- `test.ipynb`는 앱으로 만들기 전에 노트북에서 먼저 돌려 본 실험이고, `아나바다_인형.png`는 테스트에 쓴 이미지다.
- `requirements.txt`는 `pip list`로 뽑은 패키지 목록이라 커서가 읽는 참고용이다. 설치용이 아니다.

### 실습 2. 요리 추천 앱 (`작업방/요리추천앱`)

냉장고 재료를 입력하면 지금 만들 수 있는 요리를 추천해 주는 앱이다. 이번에는 바로 코드를 시키지 않고, **스킬로 아이디어를 구체화하고 기획서(PRD)를 먼저 만든 뒤** 그 문서로 코드를 만들었다.

진행 순서

1. [skills.sh](https://skills.sh)에서 `grillme`와 `to-spec` 스킬을 설치한다.
2. `/grillme`로 아이디어를 뽑는다. AI가 질문을 계속 던지면서 내 아이디어의 빈틈을 채워 준다. (이 앱은 문답 18번까지 진행했다.)
3. `/to-spec`으로 문답 결과를 PRD(`PRD.md`)로 정리한다.
4. 나온 `PRD.md`를 기준으로 코드를 작성한다.

`PRD.md`에는 해결할 문제, 해결 방법, 사용자 스토리 40개, 구현 결정, 테스트 방법, 이번에 하지 않을 것(범위 밖)이 들어 있다. 사진 인식은 범위에서 뺐고, 이 때문에 실습 1의 YOLO와는 연결되지 않는다.

앱 기능 (Gradio, 상단 메뉴로 3개 페이지 이동)

- 재료 목록: 재료명, 수량, 유통기한, 분류를 추가·수정·삭제한다. 직접 입력, 빠른 입력, 자주 쓰는 재료 선택 세 가지로 넣을 수 있다. SQLite에 저장해서 앱을 껐다 켜도 남는다. 유통기한이 D-3 이내면 "임박", 지났으면 "만료"로 표시한다.
- 추천 레시피: 가진 재료로 필수 재료가 모두 있으면 "바로 가능", 1~2개 부족하면 "조금 부족"으로 보여 준다. 임박한 재료를 쓰는 요리가 위로 올라온다. 맞는 요리가 없을 때는 "AI 레시피 생성" 버튼으로 OpenAI가 만든 "AI 추천"을 따로 받아 볼 수 있다. 저장은 하지 않고 매번 새로 만든다.
- 전체 레시피: `recipes.json`의 한식 위주 레시피 약 50개를 검색해서 본다.

구조와 테스트

- 재료 저장(`inventory_store`), 유통기한 판정(`expiry`), 재료 이름 통일(`normalize`, 달걀/계란 등), 추천 엔진(`recommender`), AI 생성(`ai_recipe`)을 `core/`에 나눠 두고 화면(`app.py`)은 불러다 쓰기만 한다.
- `tests/`에 `pytest`로 추천 엔진, 재고 저장소, 레시피 데이터, AI 응답 해석, 앱 기본 동작을 검증했다. 날짜는 고정해서 넣고, AI 호출은 테스트에서 부르지 않는다.
- OpenAI API 키는 코드에 쓰지 않고 환경 변수 `OPENAI_API_KEY`로만 읽는다. 키가 없어도 AI 추천을 뺀 나머지는 동작한다.
- 올리지 않은 것: `data/pantry.db`는 내가 입력한 재료가 담긴 개인 데이터라서 앱 폴더의 `.gitignore`로 제외했다. 처음 실행하면 새로 만들어진다.

### 3일차 정리

- 코드를 바로 시키는 것보다, 질문으로 아이디어를 다듬고 PRD를 먼저 쓴 뒤 코드를 만드니 무엇을 만들지 기준이 문서로 남았다. PRD의 "하지 않을 것"이 범위를 지켜 주는 역할을 했다.
- 같은 사물 인식이라도 Flask와 Gradio는 서버를 띄우는 방식과 포트(5000, 7860)가 다르다. Gradio는 화면 구성까지 같이 해 줘서 짧은 코드로 업로드와 웹캠 화면을 만들 수 있었다.
- 가중치 파일은 모델이 배운 결과물이라, 작으면 같이 올리고 크면 `.gitignore`로 빼서 따로 받게 한다.
