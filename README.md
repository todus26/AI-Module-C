### 프롬프트로 앱과 웹 서버 만들기 (`작업방/`)

오늘 실습의 핵심은 **요구사항을 프롬프트로 구체적으로 적어서 앱과 서버를 만들어 보는 것**이었다.
역할, 목적, 개발 환경, 폴더 구조, 기능 요구사항, 디자인, 구현 규칙, 진행 순서를 나눠서 적을수록 결과가 원하는 모습에 가까워진다는 걸 느꼈다.
앱(데스크톱)과 웹 서버, 두 종류를 모두 해 봤다.

실습은 아래 순서로 진행했다. (`flask_test`는 웹 서버를 처음 띄워 본 워밍업이다.)

#### 1. pdf분할병합 (PyQt5 데스크톱 앱)

- 분할 5가지: 페이지 선택 / 범위별 / N페이지씩 / 특정 페이지 뒤에서 / 균등 분할
- 병합: 여러 PDF를 순서 조정(드래그, 위로/아래로/삭제)해서 하나로 합치기
- 저장 전에 썸네일로 결과를 미리 보고, `수정`을 누르면 입력값이 그대로 남아 있는 상태로 돌아간다.
- 로직(`core`)과 화면(`ui`)을 나누고, 썸네일 생성과 Word 변환은 `QThread`로 처리해서 화면이 멈추지 않게 했다.
- 페이지 입력 파서는 `pytest`로 정상/경계/오류 케이스를 검증했다.
- `PyInstaller`로 `.exe` 파일까지 만들어 봤다.
- 올리지 않은 것: 실행 파일 `dist/PDF분할병합.exe`는 약 126MB라서 GitHub의 100MB 제한에 걸리고, `build/` 폴더는 다시 만들 수 있는 부산물이라 `.gitignore`로 제외했다. 아래 방법으로 직접 만들 수 있다.

**실행 파일(.exe) 만드는 법**

`pdf_tool` 폴더에서 아래를 순서대로 실행한다.

```powershell
pip install -r requirements.txt
pip install pyinstaller
python -m PyInstaller --noconfirm --clean "PDF분할병합.spec"
```

- 결과물은 `dist/PDF분할병합.exe` 하나로 나오고, 더블클릭하면 파이썬이 없는 PC에서도 실행된다. 처음 실행할 때는 압축을 푸느라 몇 초 걸린다.
- `PDF분할병합.spec`에는 창만 띄우는 설정(`console=False`), 아이콘 폴더(`resources`) 포함, `pdf2docx` 모듈 포함, 쓰지 않는 큰 라이브러리 제외가 들어 있다.
- 실행 파일 안에서는 파일 경로가 임시 폴더로 바뀌기 때문에, 아이콘 경로를 찾는 코드(`ui/styles.py`의 `icon_path`)에 `sys._MEIPASS`를 따로 처리해 두었다.
- 빌드 중 `Hidden import "sip" not found` 경고가 나와도 실행에는 문제가 없었다.

#### 2. 유튜브다운로드 (PyQt5 데스크톱 앱)

- 링크를 붙여넣고 분석하면 제목, 채널, 썸네일, 받을 수 있는 포맷 목록이 나온다.
- 영상 포맷과 음원(mp3, m4a)을 선택해 받을 수 있고, 진행률·속도·남은 시간이 표시된다.
- 분석과 다운로드는 `QThread`에서 돌려서 화면이 멈추지 않는다.
- URL 검증과 용량/시간 변환 함수는 `pytest`로 테스트했다.
- 개인적으로 이용할 수 있는 콘텐츠를 받는 용도로만 쓰는 도구다.

**실습하면서 알게 된 것**

- `pip install -U yt-dlp`
  - 유튜브 정책이 업데이트되면서 패키지 에러가 나면, 이렇게 `yt-dlp`를 최신으로 올리고 다시 진행한다.
- `winget install Gyan.Ffmpeg`
  - 4K 이상 영상은 유튜브 정책상 음성과 영상이 따로 나눠져서 내려온다.
  - 이 둘을 하나로 합치려면 FFmpeg가 필요해서 이 프로그램을 따로 설치한다. mp3 변환에도 쓰인다.

#### 3. pdf다운로드 (PDF 번역 웹 서버)

- Flask로 `/`(화면), `/upload`(PDF 업로드), `/translate/<job_id>`(번역), `/download/<job_id>`(결과 받기) 주소를 만들었다.
- PDF 텍스트를 3000자 단위로 쪼개서 OpenAI에 보내고, 번역되는 대로 화면에 이어 붙이도록 SSE(서버가 계속 데이터를 흘려 보내는 방식)를 사용했다.
- 암호가 걸린 PDF, 스캔본(텍스트 없음), 번역 실패 시 재시도 같은 예외 상황을 처리했다.
- API 키는 코드에 쓰지 않고 환경 변수 `OPENAI_API_KEY`로 읽는다.

**실습하면서 알게 된 것: 패키지 목록 정리하기 (`requirements.txt`)**

```powershell
pip list >> requirements.txt
pip freeze > requirements.txt
pip install -r requirements.txt
```

- `pip list >> requirements.txt`
  - 커서(코딩 에이전트)가 코드를 만들고 실행하려면 패키지가 설치돼 있어야 하는데, 목록이 없으면 내 컴퓨터를 돌아다니며 찾느라 시간과 토큰이 많이 든다.
  - 이 명령어로 패키지 목록을 파일로 만들어 두면 어떤 패키지가 있는지, 설치가 필요한 게 무엇인지 바로 알 수 있어서 코드를 만들기가 쉬워진다.
  - 이 파일은 **커서가 읽는 참고용**이다. 형식이 설치용이 아니라서 `pip install`로는 설치되지 않는다.
  - `>`는 파일을 덮어쓰고, `>>`는 기존 내용은 두고 뒤에 이어 붙인다.
- `pip freeze > requirements.txt`
  - 내 코드를 다른 사람에게 주려면 상대방에게도 파이썬이 있어야 하고, 내가 쓴 것과 같은 버전의 패키지가 설치돼 있어야 한다.
  - `pip freeze`는 내 PC에 설치된 패키지를 `패키지==버전` 형식으로 뽑아 준다.
- `pip install -r requirements.txt`
  - 받은 사람이 이 명령어를 실행하면 파일에 적힌 버전 그대로 한 번에 설치된다.

#### 4. 아나바다 (Flask 웹 서버, DB 반영)

- 회원가입, 로그인, 로그아웃 (비밀번호는 해시로 저장)
- 물건 등록, 수정, 삭제, 거래가능/거래완료 상태 전환, 이미지 업로드
- 로그인한 사람만 접근하는 주소에는 `@login_required`, 폼에는 CSRF 보호를 적용했다.
- 데이터는 SQLite와 SQLAlchemy 모델(`User`, `Item`)로 DB에 저장하고, 서버를 껐다 켜도 회원과 물건이 남는다.
- 올리지 않은 것: `instance/secret_key`(로그인 세션 서명 키)와 `instance/anabada.db`(가입한 계정과 물건 정보)는 보안과 개인 정보 문제로 제외했다. 둘 다 처음 실행하면 자동으로 만들어지므로 `python app.py`만 실행하면 된다.

### 오늘 정리

- 함수, 람다, 클래스를 배운 직후에 앱과 서버를 만들어 보니, 배운 문법이 실제 코드에서 어떻게 쓰이는지 바로 볼 수 있었다.
- 프롬프트는 "무엇을 만들지"만이 아니라 폴더 구조, 예외 처리, 디자인 규칙, 진행 순서까지 적을수록 결과가 안정적이었다.
- 화면(UI)과 로직을 분리하고, 오래 걸리는 작업은 별도 스레드로 빼는 구조를 이해했다.
- 비밀키, 데이터베이스, 실행 파일처럼 저장소에 올리면 안 되는 파일을 `.gitignore`로 거르는 방법도 익혔다.
